# 順序回路 学習ラボ（sequential-lab）

論理回路の授業（第16〜22回）の練習問題を、シミュレーションしながら解くための学習ツール。

## 起動方法

```
npm install
npm run dev
```

表示された URL（通常 http://localhost:5173）をブラウザで開く。

## テスト

```
npm test          # Vitest
npm run typecheck # 型チェック
```

## 画面の使い方（フェーズ2：タイミングチャート）

- 左の一覧から場面（授業の回路）を選ぶ。
- **次のエッジへ ▶**（または → キー）で、入力が変化する時刻を1つずつ進む。FF が動くクロックエッジと、CLR などの入力の変化がステップになる。← キーで戻る。
- チャートの黄色い帯がいまのステップ。そのステップで変化した信号は、行が濃い黄色になる。出力の波形はいまのステップまでしか描かない（「先の波形も表示する」で全部見える）。
- 縦の点線は FF が動くクロックエッジ。立下りで動く回路は赤、立上りで動く回路は青。上の数字はエッジの回数。
- 下のパネルに、状態がたどった値（例：(100) → (101) → (000)）、変化の順番（例：0ns Cₚ立下り → 8ns Q₀反転 → 16ns Q₁反転）、変化ごとの理由が出る。
- **時間モデル**：「遅延あり（標準）」と「理想（遅延なし）」を切り替える。遅延ありでは FF・ゲート・配線の遅延（ns）をスライダーか数値で変えられる。
  - 17-2／17-3 は、リセット信号 → FF₀ の配線遅延を変えて、誤動作する／しないを確かめられる。「配線の遅れ方」で、短いパルスが消える方式（標準）とそのまま遅れて届く方式を切り替える。
- **時間軸**：−／＋／スライダーで拡大・縮小。「このエッジを拡大」で、いまのステップの遅れ（+8、+16 …）が見える倍率になる。
- **多ビット信号を16進のバス表示にする**：(A₃A₂A₁A₀) などを X3、XA の形で1行にまとめる（第19回の表記）。
- 右の**動作表**は、クロックの回数ごとの落ち着いた後の値。いまのステップの行が黄色になる。
- **回路図**（第16〜20回）：チャートの上に表示する。配線は H（1）がオレンジ、L（0）がグレーで、いまのステップが終わった時点の値を示す。いまのステップで変化した信号は太い線になる。FF のクロック端子の丸印は立下りトリガ、CLR／PR の丸印は負論理。
  - URL の末尾を `#gallery=1` にすると、全回路の回路図を一覧できる（配置の確認用）。
- 表示中の場面とステップは URL（# 以降）に残るので、再読み込みしても同じ場所に戻る。

## 画面の使い方（フェーズ4：問題モード）

左上の「問題」を押すと問題の一覧になる。解いた問題には ✓ が付き、ブラウザに記録される（記録できない環境では、記録なしで動く）。

- **タイミングチャートの穴埋め**：青い行が答える信号。マス（クロックの半周期）をクリックすると H → L と切り替わる。ドラッグで続けて塗れる。Shift+クリックで消す。多ビット信号は、マスごとに16進の1文字を入力する（X は付けない）。
  - 「採点」で、まちがいのマスが赤、空欄が黄色、正解が緑になる。採点は遅延なしの理想波形で行う。
  - 灰色のマスは、CLR や PR でマスの途中に値が変わるところ。H/L の1つでは表せないので、最初から波形を見せて採点しない。
  - (101) のように一瞬だけ現れる値は描かない（マスには落ち着いた後の値を入れる）。
  - 「解説を見る」で、その回路のシミュレーション画面（ステップ実行）に移る。
- **動作表の穴埋め**：マスをクリックすると 空欄 → 0 → 1 と切り替わる。
- **選択・数値問題**：FF の個数、カウンタの名称（同期式か非同期式か、何進か、アップかダウンか）など。
- **記述問題**：解答例を開いて見比べる（開くと解いた記録が付く）。
- 「正解を表示」した後の採点は、解いた記録に付けない。「クリア」してから自分で解くと記録される。

## 画面の使い方（フェーズ5：設計ガイド）

左上の「設計」を押すと、授業の「拡大入力要求表を使う設計方法」を上から順に進める画面になる。

1. **仕様**：同期N進カウンタ（2〜16進、アップ／ダウン）か、状態遷移表（ミーリー型／ムーア型）を選ぶ。授業の例（自動販売機、3進カウンタのムーア型、ストップウォッチ）を読み込める。表のマスは書き換えられる。「空の表を作る」で自分の表も作れる。
2. **状態の符号化**：自動（上から 0, 1, 2 …）か、2進数を手で入力する。使わない符号の行は don't care（X）になる。
3. **拡大入力要求表**：使う FF（D／JK／RS／T）を選ぶ。「列を自分で埋める」にすると、FF の入力の列を自分で埋めて採点できる（マスは 空欄 → 0 → 1 → X）。
4. **カルノー図と論理式**：FF の入力と出力ごとにカルノー図が出る（行と列はグレイコード順）。マスを選んで「グループにする」で囲む。論理式を入力して「判定」を押すと、真理値表の全行（X を除く）と照合する。
   - 式の書き方：否定は後ろに `'`（`Q1'Q0' + Q0`）か、前に `~`。積は並べて書く。和は `+`。排他的論理和は `^`。定数は `0` と `1`。
   - 結果は「正解（最小積和形と同じ大きさ）」「正しいが最小ではない」「合わない（合わない行を表示）」のどれか。
5. **回路を作って確かめる**：最小積和形の式から回路を作り、シミュレーションの画面（タイミングチャート、ステップ実行、動作表）で動かす。状態遷移表の回路は、入力を D-FF でラッチしてから使う（授業の回路と同じ形）。作った回路の回路図は表示しない。

  - `build.ts` 回路を書くための補助（`ff`、`gate`、`wire` など）
  - `stimulus.ts` クロックと入力の刺激列を作る補助
  - `sample.ts` 結果から値・動作表・バスの履歴を読む補助
- `src/problems/circuits.ts` 授業の回路
- `src/problems/problems.ts` 問題（穴埋め・動作表・選択／数値・記述）
- `src/problems/scenes.ts` 場面（回路＋入力波形＋表示する信号＋遅延の初期値）
- `src/view/` 表示用のデータ整形（UI に依存しない TypeScript。テストあり）
  - `label.ts` 信号名の表記（添字・上線）
  - `steps.ts` ステップ実行と変化の理由の文章
  - `chart.ts` 波形、バス表示、動作表、時間軸の目盛り
  - `grade.ts` 問題の正解づくり（マスごとの値、カウンタの種類）と採点
- `src/design/` 設計ガイドの中身（UI に依存しない。テストあり）
  - `fsm.ts` 仕様（状態遷移表）、符号化、入力要求、拡大入力要求表
  - `minimize.ts` 最小積和形（クワイン・マクラスキー法）、カルノー図の並びとグループの判定

- `src/ui/` 画面（React + SVG）

## エンジンの考え方

- 時間の単位は ns。授業の回路はクロック周期 100ns で動かしている。
- **理想モード**（`mode: 'ideal'`）は遅延 0。同じ時刻の中で、原因 → 結果の順に番号（delta）を付けて処理する。同じエッジで動く FF は、エッジ直前の入力を読む。
- **遅延モード**（`mode: 'delay'`）は、FF（既定 8ns）、ゲート（既定 5ns）、配線（`wire` で名前を付けた配線ごと）に遅延を持つ。
- 配線遅延は「遅延より短いパルスは消える」（慣性、標準）と「そのまま遅れて届く」（`wireModel: 'transport'`）を選べる。
- CLR が働いている間は、クロックエッジを無視する。CLR と PR が同時に働いたら CLR を優先する。
- 変化ごとに理由（クロックエッジ・エッジ直前の入力・動作、CLR／PR、ゲートの入力）を記録する。

## 場面の追加方法

`src/problems/scenes.ts` の `SCENES` に1件足す。

```ts
{
  id: '16-4',                    // 一意な名前（URL にも使う）
  lecture: 16,                   // 授業回（一覧のまとめ方）
  title: '練習4 D-FFによる非同期8進アップカウンタ',
  source: '16 p.7',              // スライドの場所
  circuit: c.c16_4,              // src/problems/circuits.ts の回路
  clock: 'cp',                   // クロックの信号名
  edge: 'falling',               // FF が動くエッジ
  stimulus: withInputs(fall(10), { clr: 1 }),  // 入力波形。k 番目のエッジが t = 100k ns
  rows: ['cp', 'q0', 'q1', 'q2'],              // チャートに並べる信号（上から）
  stateBits: ['q2', 'q1', 'q0'],               // 動作表と状態表示に使うビット（上位から）
  delays: { ff: 8, gate: 5 },                  // 遅延の初期値（ns）
  // 任意：init（FF の初期値）、labels（表記の上書き）、wires（遅延を変えられる配線）、
  //       busView（最初からバス表示）、note（補足）、annotate（ステップごとの補足）
}
```

- 表記の書式：`'Q_0'` → Q₀、`'~Q_1 ~Q_0'` → Q̄₁Q̄₀、`'C_p'` → Cₚ。空白で区切った部品を並べ、`~` は上線、`_` の後ろは添字。
- 入力波形をスライドから書き起こした場面は、`tests/fixtures/scenarios.ts` の期待値と同じ刺激列であることを `tests/problems/scenes.test.ts` で確認している。

## 問題の追加方法

`src/problems/problems.ts` の `PROBLEMS` に1件足す。**答えは書かない**（記述問題の解答例を除く）。

```ts
// タイミングチャートの穴埋め：場面と、空欄にする信号を指定する。正解はエンジンが計算する。
{ kind: 'timing', id: '16-4', lecture: 16, title: '…', source: '16 p.7', statement: '…',
  sceneId: '16-4', blanks: ['q0', 'q1', 'q2'] }          // 多ビット信号は busBlanks: ['Q']

// 動作表の穴埋め
{ kind: 'table', id: '18-p3', …, sceneId: '18-p3' }

// 選択・数値：answer は、回路の解析（kindOf）か、問題の条件からの計算で求める関数
{ kind: 'quiz', id: '16-ex1', …, questions: [
  { kind: 'number', prompt: 'FF の最低個数', unit: '個', answer: () => Math.ceil(Math.log2(64)) },
] }

// 記述：解答例を折りたたみで表示する
{ kind: 'essay', id: '22-ex2', …, answer: ['…'] }
```

- 選択・数値問題を足したら、`tests/problems/problems.test.ts` の `SLIDE_ANSWERS` にスライドの答えを書き起こす（計算した答えと一致することを確かめるため）。

## 回路図の追加方法

`src/schematic/layouts.ts` の `LAYOUTS` に配置を書く。キーは回路の id。場面ごとに図を変えたいときは場面の id をキーにする（例：17-2 は 17-1 と同じ回路だが、スライド p.3 の専用の図）。

```ts
'18-p3': {
  width: 580, height: 262,
  ffs: { ff0: [120, 90], ff1: [240, 90], ff2: [440, 90] },   // FF の左上の座標（大きさは 60×60）
  gates: { a01: { at: [350, 26] } },                          // ゲートの左上。dir: 'left'（左向き）／'down'（下向き）
  tracks: { cp: 168, $1: 58 },                                // 横の母線の y（信号名。定数は $1／$0）
  outputs: ['q0', 'q1', 'q2'], outY: 216,                     // 下へ引き出して名前を書く信号
  ffNames: true,                                              // FF の名前を箱の上に書く
}
```

そのほかに書けるもの：

| 項目 | 意味 |
|---|---|
| `ports` | 外部入力の端子の位置（上から入る入力など）。3つ目に `'left'` を書くとラベルが左 |
| `taps` | 母線ではなく、出どころの縦線へ横につなぐ端子（例：`'ff1.ck'`、`'rst.in0'`） |
| `spineX` | 出どころの縦線の x を、出どころから離す |
| `outRight`／`outLabels` | 右へ引き出す信号と先端の x／引き出した先に書く名前の上書き |
| `pinIndex: false` | 端子名を添字なしにする（D、Q） |
| `notes`／`frames` | 説明の文字／点線の枠 |
| `dashed`／`breaks` | 点線で描く範囲／長い配線の省略記号 |
| `leds`／`extra` | LED の記号（飾り。信号が 0 で点灯）／そこへつなぐ線 |

- 配線は自動で引く。tracks に書いた信号は「横の母線＋各端子への縦線」、書いていない信号は「出どころから縦線を引き、各端子の高さで横につなぐ」。同じ FF の J と K が同じ信号につながるときは、1本の縦線から分岐する。
- 接続は回路データ（`src/problems/circuits.ts`）から取るので、配置を変えても電気的な意味は変わらない。
- `tests/schematic/layout.test.ts` が、線が素子の中を通らない・別の信号の線と重ならない・全端子につながる、を全回路について検査する。配置を足したらテストと `#gallery=1` の両方で確かめる。
